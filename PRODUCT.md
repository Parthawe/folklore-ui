# Folklore

<!-- impeccable:product-schema 1 -->

## Platform
web

## Stack
Astro, TypeScript, native CSS; static output. Approved in the implementation plan.

## Users
Designers and developers who can describe an interface or visual style but need its terminology and implementation vocabulary.

## Product Purpose
Translate descriptions into named patterns, working demonstrations, anatomy, source references, and useful build or debug prompts.

## Operating Context
Browse the public website or install the offline Codex skill/plugin. One catalog supplies both. No model API, accounts, telemetry, or hosted search service in v1.

## Capabilities and Constraints
Thirty elements across web and macOS, ten styles, text search, comparisons, local bookmarks, Markdown export, offline lookup scripts, a task-aware design-review planner, and a fifteen-source research library. The review planner uses local English keyword/phrase rules, not a model or screen inspection; its exported brief supports a real project review in Codex. Browser macOS specimens are simulations. Source and site are public. MIT license for original work.

## Brand Commitments
Folklore is the product name. Original identity and content; Name That UI supplies the reference workflow. The first visual design was rejected on 25 November 2026. The user chose an interactive specimen desk with one large working example, clickable anatomy, and a compact searchable index. Hosting belongs on GitHub Pages, not Sites. On 26 November 2026, the user requested a screen audit and the dark editorial visual language of designwhich.works. Retain the specimen desk while adapting typography, framing, spacing, and navigation to that reference.

## Evidence on Hand
The approved plan and live reference workflow. API claims require primary documentation. No customer claims, endorsements, or usage metrics.

## Product Principles
- Show the mechanism before asking the reader to trust a name.
- Preserve platform and framework distinctions.
- Share content between browser and agent outputs.
- Keep installation usable without a service or API key.

## Design review surface

The /review/ workflow takes a task, optional audience, optional screen description, and editable task type. It separates reported risks, untested task checks, preservation guidance, pattern suggestions, and a Codex brief. Input is not uploaded or saved. No AI-authorship probability, slop score, or compliance certification is produced. /review/references/ distinguishes standards, usability guidance, and Folklore’s editorial judgments. The downloadable screen-audit skill v1.2.1 shares the local planner and research guide.

Preserve the Paper-inspired editorial shell and compact desk while adapting operational controls with a system UI font stack, segmented choices, and restrained blue actions. The website remains a semantic web interface.
